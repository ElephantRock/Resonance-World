# Research-First Execution Contract — عقد التنفيذ البحثي أولًا

**الحالة:** ملزم. يقرأه المنفّذ (DSH) والمراجع قبل كل تكليف.
**المصدر:** قرار صاحب المشروع 2026-10-26، بعد تشخيص انحراف G1 v9 إلى هندسة مفتوحة النهاية.

## المهمة العليا

Resonance World مشروع لاكتشاف وإثبات القدرات الناشئة للوكلاء والمنظمات والمؤسسات:
الانتقال من Models إلى Agents إلى Agent Organizations إلى Autonomous Institutions.
**المنصة أداة لخدمة الفرضيات، وليست منتجًا قائمًا بذاتها ولا معيار نجاح المشروع.**

## القواعد الخمس الملزمة

1. **لا تبدأ مهمة هندسية دون ارتباط بفرضية.** كل عمل جديد يحدد ثلاثة أمور:
   الفرضية العلمية التي يخدمها، والعائق الفعلي الذي يزيله، والدليل الذي يصبح
   ممكنًا بعد انتهائه. إن كانت الإجابة «زيادة متانة» أو «تحسين مستقبلي» →
   قائمة مؤجلة.

2. **مراجعة القبول ليست تفويضًا بتوسيع النطاق.** معايير القبول تُثبَّت قبل
   المراجعة. بعد إغلاقها لا تُفتح ملاحظة مانعة جديدة إلا بفشل حرج قابل للتكرار
   يؤثر على التجربة الحالية. التصنيف صارم:
   - **P0 مانع حقيقي:** خطر تشغيلي معتبر أو خلل يُفسد النتيجة، بدليل قابل
     للتحقق وسيناريو فشل محدد وأثره على التجربة الجارية → إصلاح قبل التجربة.
   - **P1 مهم غير مانع:** يؤجل لما بعد التجربة.
   - **P2 مستقبلي:** قائمة التطوير اللاحقة.
   لا يحق لأي طرف ترقية ملاحظة إلى P0 دون سيناريو فشل محدد وتأثيره على
   التجربة الحالية.

3. **سقف للمراجعات، لا سقف للسلامة.** كل بوابة: مراجعة أساسية + جولة تصحيح
   واحدة للتحفظات المحددة. ما يبقى بعدها يُرفع لصاحب القرار لإعادة تحديد
   النطاق أو قبول التأخير — قرار إداري واعٍ، لا نتيجة تلقائية لملاحظة.

4. **حجز معظم الموارد لإنتاج الأدلة.** التوزيع المستهدف: تنفيذ التجارب
   وتحليل الأدلة 80%، الهندسة والصيانة الضروريتان 20%. عدة جولات متتالية
   بلا تجربة جديدة = توقف وإعادة تقييم أولوية.

5. **الإنجاز لا يُقاس بعدد الاختبارات البرمجية.** نجاح الاختبارات شرط جودة،
   لا بديل عن النتائج العلمية. تقرير التقدم يجيب: ما الفرضية التي اختبرناها؟
   كم تجربة أُنجزت على النظام الفعلي؟ ما الأدلة؟ ما الذي تعلمناه وإن فشلت
   الفرضية؟ ما القرار العلمي التالي؟

## توزيع السلطة

| الدور | الصلاحية | ما لا يفعله |
|---|---|---|
| صاحب المشروع | الأهداف، أولويات الفرضيات، حدود الوقت والموارد | لا يترك ترتيب الأولويات لسلسلة مراجعات تلقائية |
| DSH — المنفّذ | أقل جهاز كافٍ، تنفيذ التجارب، تقديم الأدلة | لا يحوّل كل ملاحظة إلى برنامج تطوير مستقل |
| الباحث/المراجع | تصميم الاختبار، تقييم الأدلة، المخاطر الحرجة | لا يوسّع النطاق بعد القبول دون مبرر تجريبي |
| المشغّل المخوّل | الأسرار، التفويض، الإنفاق، الإرسال الحي | لا يخلط إذن التشغيل بصلاحية الادعاء العلمي |

**كل مراجعة تنتهي بقرار انتقال أو توقف — لا بقائمة مهام جديدة.**

## السؤال الحاكم

> «هل يوجد خلل مثبت يمنعنا من تنفيذ التجربة الحالية بأمان، أو يجعل نتائجها
> غير صالحة علميًا؟» — وليس «هل أستطيع اكتشاف خلل آخر؟».
> الأول يسمح بقرار؛ والثاني لا ينتهي تقريبًا.
