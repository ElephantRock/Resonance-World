# C3R G1 Acquisition Pilot v1.0 — three-arm offline construction

**State: unfrozen, synthetic, local-only, no scientific inference or live-model authorization.**

This prototype answers a narrow apparatus question: can a prospective
three-arm G1 evaluation keep feedback separated, evaluate the same heldout
tasks, preserve failed attempts, and aggregate outcomes at the **learner-unit**
level rather than treating each question as an independent learner?

It does **not** answer whether GLM-5.3 learned. It does not reuse, reinterpret
or rerun the two historical Z.AI smokes (16-token: 0/8 accepted; corrected
512-token: 5/8 accepted but 0/2 analyzable learned/fresh pairs).
See `ONE_SHOT_ARTIFACT_ANALYSIS_20261022.md` and
`OUTPUT_BUDGET_REQUALIFICATION_20261022.md`.

## Command (zero network; zero credentials)

```bash
python -m resonance_world.c3r_g1_pilot
```

Outputs deterministic canonical JSON labeled
`offline_fixture_only_no_scientific_inference`. This path injects
synthetic constant-A policy ports. It never imports a provider client,
accesses credentials, or executes GitHub Actions.

## Prospective mechanical design

| Attribute | Default offline design |
| --- | --- |
| Logical, freshly reset learner units | 8 |
| Opaque within-schema contexts per unit | 2 |
| Source development tasks per context | 6 |
| Heldout tasks per context | 8 |
| Learned source development requests | 96 |
| Heldout task triplets (same task across all arms) | 128 |
| Heldout requests (3 arms per triplet) | 384 |
| **Total prescribed port calls** | **480** |
| Actual external model sends in this command | **0** |

The bound `required_calls <= 480` is an **offline logical-work cap**,
not a trustworthy provider transport or billing limit. No real-model
adapter is injected here. A future live campaign needs an independent
pre-send physical cap, a service-side billing guard, credential authorization,
and a newly approved protocol.

**Important limitation:** The two contexts per unit are different
context-to-plan rules **within the same two-operation arithmetic task
schema**. They are **not two genuinely different task families**.
Out-of-schema transfer cannot be inferred from this fixture.
The hidden rule is reproducible from the local fixture seed, and the local
evaluator has no secure process boundary. For real science, a separate
evaluator must own hidden targets and sign/attest its prospective lock.

## Three arms and information isolation

**Learned:** a separately created development port chooses each development
action before seeing the true grade. Only accepted graded development actions
receive post-action Boolean feedback. The accumulated history is passed
back on later development tasks. **After source training, the development
port is discarded and a second, separately constructed trained-arm port
handles qualification**, receiving only the explicitly persisted accepted
feedback for its context. This checks that the observable treatment can be
reconstructed across an interface-level session reset; it does **not**
prove actual provider backend-session independence. No qualification grade
is ever fed back.

**Fresh:** a distinct freshly created port receives each identical heldout
public task but no development records or qualification grades.
Its first choice is not privileged by the evaluator. Source-training
expenditure is recorded separately; no claim of equal **total**
training+qualification compute is made.

**Placebo-context:** a third distinct port sees the same accepted
development task identifiers and plan traces as the learned arm, but
with sham Boolean labels generated by a preregistered fixture-specific
pseudorandom rule unrelated to the private target grade. This controls
for exposing plan/task history. **It is not a perfectly blinded, exactly
token-matched, or guaranteed uninformative placebo.** Some policy signal
can remain in the sequence of plans selected by the learned arm; this
makes the control conservative in some settings and confounded in
others. Qualifying this control requires a separate bias/leakage study.

All arms see exactly the same public operands at qualification, in a
rotated within-task order. The `model_id` must match the design lock
whenever a completion is accepted. The same port object cannot be
reused between source development and trained qualification, across arms,
or across learner units. The default 8-unit fixture thus creates 32
separate logical port objects, but still makes only 480 local calls. This is a **structural** safeguard:
distinct Python objects cannot prove independent remote model sessions,
absence of provider caching, or matching temperatures and tool budgets.

## What the report means

The primary descriptive score treats every nonaccepted attempt as
failure (**intention-to-treat**, ITT), with the prescribed count as the
denominator. For each learner unit:

```text
ITT learned - fresh = (learned successes - fresh successes) / heldout tasks per unit
ITT learned - placebo = (learned successes - placebo successes) / heldout tasks per unit
```

The report gives unit-by-unit values and an **unweighted mean across
the eight learner units**, not across 128 pooled task triplets.

Technical output quality is reported independently:
- `qual_action_yield`: total accepted / 384 prescribed holdout
  calls, including exceptions and invalid strings in the denominator.
- `heldout_triplet_yield`: heldout tasks where all **three** arms
  supplied an accepted answer / 128 prescribed triplets.
- `qualification_by_arm`: accepted/ITT-success and each failure status
  for each of the three treatments.
- `development_accepted` and `history_exposure_counts`: expose loss
  of graded source feedback rather than silently pretending the treatment
  history was complete.

The proposed **engineering gate** requires at least 95% qualification
action yield, at least 90% full-triplet yield, and parseable source
development actions. These are **proposed technical thresholds**, not
universally valid scientific minima. A passing fixture never authorizes
a provider run or an inference.

The report always sets:
`statistical_test_performed=false`,
`independent_evaluator_attested=false`,
`actual_provider_sends_verified=false`,
`scientific_acceptance=false`.

## Required negative controls (automated)

- Null constant-A policies for all three arms produce exactly **zero**
  treatment contrast with complete prescribed denominators.
- A deterministic feedback-responsive local port improves the learned
  arm; this checks the treatment wiring only, **not model learning**.
- Trained/fresh/placebo cannot reuse the same model-port object; source
  and qualification feedback cannot cross contexts or leak target grades.
- Wrong model IDs, adapter exceptions, malformed model answers and
  missing feedback are accounted for, **not discarded**.
- Identical task IDs or public payloads across splits or units violate
  the frozen `PilotLock`.
- A forged change to the evaluator rule need not change the **public**
  cohort digest; the missing private evaluator commitment is explicit.

## Entry gates for a separately authorized live G1 pilot

1. **Calibration:** a *different* technical cohort must show stable A/B
   production under one fixed token/latency configuration, with an
   audited provider-side spend cap and per-arm logging.
2. **Port/session matching:** same pinned model version, temperature,
   token/time/tool budgets across qualification arms, new model sessions,
   and provider-verified send accounting; isolate the evaluator process.
3. **True multiple schemas:** add genuinely different task-generation
   families, not merely more operand values of the same arithmetic
   template. Ensure no public payload collisions or prompt leaks.
4. **Placebo validation:** verify sham labels contain no answer-key
   information beyond chance and examine plan-history leakage; calibrate
   exposure length/tokens and context windows for both treatment arms.
5. **Causal registration:** preregister the expected effect size, power,
   number of independent learners, allocation procedure, attrition
   strategy, heldouts, primary ITT estimator and stop rule. Use
   cluster-aware inference on learner units, not task-count p-values.
6. **Replication:** repeat with evaluator-owned splits, distinct learner
   cohorts, blind protocol checks and a source-holdout boundary. If the
   G1 effect replicates, then design G2 with fully fair raw-history
   and role controls, separately.

Nothing in this pilot promotes pattern registers, mechanism registries,
D2/W/H claims, frozen outcomes or autonomous-institution hypotheses.
