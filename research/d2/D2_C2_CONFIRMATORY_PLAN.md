# D2-C2 confirmatory plan v0.1

Status: **prospective fresh-data confirmatory successor; zero D2-C2 provider calls at this freeze.**

Program issue: #180. Parent D2 program issue: #167.

## 1. Purpose and C1 boundary

D2-C1 was a valid prospective confirmatory attempt whose marker/candidate integrity gate passed, but its monolithic provider process was cancelled at the frozen 300-minute job timeout before it emitted a provider artifact. No frozen-output evaluation ran and no inferential D2 classification exists from C1. The C1 request stream and seed namespace are retired and must never be rerun.

D2-C2 asks the **same scientific D2 question** using fresh identities/seeds/cases and an execution architecture that durably preserves disjoint provider shards. C2 is not a posthoc child mechanism and does not alter the treatment based on unavailable C1 outcomes. The only repair motivated by C1 is execution topology/durability.

Production/default Historical Substrate remains OFF. No D2 result can promote the registry automatically.

## 2. Scientific question

Can the R2 stochastic model-mediated development mechanism reproduce a locally developed specialist capability in fresh destination Fields, beyond description-only practice, while preserving at least 90% of source-developed accuracy and without exporting source-private learned state?

This remains a single-model synthetic individual-agent mechanism claim. It is not a model-weight-learning, cross-model/provider, naturalistic, team/swarm/institution, composition, market, or environment-spawning claim.

## 4. Experimental unit and arms

Experimental unit: one fresh C2 Field pair sharing one hidden local policy.

Within each pair:

1. `source_developed`: source-local development + labeled feedback.
2. `reproduced`: destination-local development + public Capability Artifact + labeled feedback.
3. `description_only`: same destination-local practice schedule but no labels/outcome-bearing feedback.
4. `fresh`: no development.

All four arms are evaluated on the same 32 held-out cases for the pair. Source and destination development feature tuples are exactly disjoint, and all development tuples are disjoint from evaluation tuples.

Attempted pairs: **360 fixed**. Minimum analyzable N: **330**. No pair replacement, imputation, outcome-adaptive N increase, efficacy/futility stopping, threshold retuning, or confirmatory request-stream rerun.

A pair is analyzable only when all four arms complete the frozen logical-call contract and all pair-level integrity checks pass.

## 6. Primary estimands

All scores are held-out accuracy proportions on the 32 frozen evaluation cases.

### P0 — source development

`P0_i = source_developed_i - fresh_i`

SESOI: +0.10. Primary null: mean(P0) <= 0.10. Alternative: mean(P0) > 0.10.

Threshold provenance: `conventional_materiality`.

### P1 — reproduction beyond description

`P1_i = reproduced_i - description_only_i`

SESOI: +0.10. Primary null: mean(P1) <= 0.10. Alternative: mean(P1) > 0.10.

Threshold provenance: `conventional_materiality`.

### P2 — reproduction fidelity

`P2_90_i = reproduced_i - 0.90 * source_developed_i`

Primary null: mean(P2_90) <= 0. Alternative: mean(P2_90) > 0.

Threshold provenance: `conventional_fidelity`; the criterion is 90% preservation of source-developed accuracy.

The raw reproduced-minus-source difference and aggregate reproduced/source ratio are reported diagnostically but do not replace the registered P2 test.

## 7. Statistical constitution

One-sided alpha: 0.05.

Primary family uses fixed serial gatekeeping:

`P0 -> P1 -> P2`

Each contrast uses the frozen large-sample paired normal test across Field pairs:

- arithmetic mean of paired contrast;
- sample SD / sqrt(N) standard error;
- one-sided p-value against registered threshold;
- one-sided 95% lower confidence bound;
- two-sided 95% normal confidence interval.

Raw and Holm-adjusted p-values are reported diagnostically. Classification authority remains the serial gatekeeping contract.

Sensitivity analysis remains the deterministic paired percentile bootstrap with 50,000 resamples and RNG seed 2026081516. Bootstrap results cannot rescue a failed primary gate.

## 10. Durable provider-shard topology

C2 replaces C1's monolithic in-memory 360-pair process with a deterministic immutable shard map:

- 18 provider shards;
- 20 registered pair indices per shard;
- shard 0 = pairs 0..19, shard 1 = 20..39, ..., shard 17 = 340..359;
- local provider-call concurrency = 1 inside each shard;
- GitHub matrix `max-parallel = 4`;
- aggregate provider-call concurrency ceiling = 4;
- target timeout = 240 minutes per provider shard;
- 620 logical calls before retries per full 20-pair shard;
- no shard/job rerun after provider execution starts.

Each successful shard emits an **unclassified** immutable shard artifact containing exactly its registered pair range, transport accounting, cohort summary, and hashes of the plan/request/cohort/shard-map records.

A shard may not execute a pair outside its registered range. Pair ranges cannot be reassigned, regenerated, or replaced.

## 11. Missing shard policy and canonical aggregation

A separate credential-free aggregator runs after provider shards, including when one or more shards are absent.

For each registered shard:

- valid shard artifact -> retain its exact pair records;
- missing shard artifact -> its 20 registered pair indices become explicit failed attempted pairs with no synthetic action/score/strategy/provider data;
- corrupt, duplicate, overlapping, foreign, pre-classified, model-drifted, request-plan-drifted, or cohort-drifted shard data -> aggregation integrity failure and therefore D2-S4.

The aggregator outputs one canonical unclassified 360-attempt provider record sorted by pair index. It may synthesize only missingness placeholders, never scientific outcomes.

One completely missing shard leaves at most N=340 and can remain classifiable if all other gates pass. Two completely missing shards leave at most N=320 and therefore necessarily produce D2-S4 under the unchanged minimum-N rule.

Missingness is not repaired by job rerun or replacement data.

## 12. Evaluator separation

Provider shards cannot classify D2. The aggregator cannot classify D2.

`scripts/evaluate_d2_c2_confirmatory.py` is the only inferential classifier. It runs without provider credentials and independently:

- verifies canonical provider-output schema and hashes;
- verifies aggregation integrity;
- reconstructs every complete pair's fresh C2 cases from the frozen generator/seed contract;
- verifies pair lock records and evaluator-private case IDs/truth;
- recomputes all arm scores from frozen actions/truth;
- verifies per-arm logical-call accounting and reproduced/description-only equality;
- applies the minimum-N rule and P0/P1/P2 statistical constitution;
- emits exactly one bounded class D2-S0 through D2-S4.

Evaluator reruns over identical canonical provider output must be byte-identical.

## 13. Classification

- D2-S0: integrity classifiable, N>=330, P0 fails.
- D2-S1: P0 passes; P1 fails.
- D2-S2: P0 and P1 pass; P2 fidelity fails.
- D2-S3: P0, P1, and P2 all pass under serial gatekeeping.
- D2-S4: apparatus/treatment-integrity failure or N<330; scientifically unclassifiable.

A missing shard alone is not automatically an integrity defect if it is represented exactly as preregistered missing attempted pairs. Corrupt/mismatched shard input is an integrity defect.
