## Router

The public task interface contains a frozen `state_relevance_key`: `procedure_rate_comparison` for routine transfer and `none` for the two non-routine families.

- `no_state`: state channel absent.
- `always_state`: state channel always present; routine gets the deterministic compiled procedure digest, non-routine gets only `status=not_applicable`.
- `selective_state`: state channel present iff `state_relevance_key=procedure_rate_comparison`.

The router is deterministic and outcome-blind. It may not inspect Plane K, correct action, model outputs, replicate outcomes, or post-treatment signals.

The prospective clarification on #156 defines the non-routine byte-identity gate over deterministic model-visible apparatus before independently sampled analyst reports are appended: analyst prompts, chair scaffold, protocol, member identity, offered actions/notices, task rule, and evidence interface. On routine cells, selective-state and always-state protocols/scaffolds must be identical.

## Primary confirmatory contrast

P1: on the four fresh routine-transfer units, matched `selective_state` versus `no_state` across 12 replicates, paired n=48. Exact one-sided paired discordance/McNemar test, α=0.05.

Gate 13 requires all of:
1. selective-state correctness exceeds no-state correctness;
2. correctness difference ≥ 0.10;
3. one-sided exact p ≤ 0.05.

There is one inferential primary contrast, so no multiplicity correction is required. Replicate directions are secondary diagnostics only.

## Routing/isolation architecture gate

Non-routine selective/no-state deterministic model-visible apparatus must be identical; routine selective/always state representation must be identical and reconstructible from the same six records.
